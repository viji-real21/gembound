# GitHub portfolio signal: quality versus repo count

**Research snapshot:** 2026-08-25  
**Answer:** Use a **curated public body of work**, led by 3–5 exceptional pinned projects. More repositories help only when each adds a different, credible proof point.

| Scenario | Best portfolio shape | Why it signals well |
|---|---|---|
| **Starter / no formal experience** | **3–5** role-relevant projects: a polished app, a deeper technical project, and ideally an outside contribution. | GitHub recommends 3–5 diverse, relevant pins and says OSS demonstrates collaboration. [GitHub](https://docs.github.com/en/account-and-profile/tutorials/using-your-github-profile-to-enhance-your-resume) |
| **Experienced engineer** | The same pins plus a short profile README with role, domain, and public proof. | GitHub recommends using the README for experience and project context; do not substitute confidential delivery with toy repos. [GitHub](https://docs.github.com/en/account-and-profile/tutorials/using-your-github-profile-to-enhance-your-resume) |
| **Founder / collaborator seeker** | One or two active flagships, a clear ask, and a few supporting proofs. | Contribution guidance, a conduct code, and license make it easier to contribute. [GitHub](https://docs.github.com/en/communities/setting-up-your-project-for-healthy-contributions) |
| **Startup / founding-engineer applications** | Show work you can explain end-to-end: live product, decisions, outcomes. | YC listings ask for GitHub/portfolio and what candidates built or shipped. [Digipals](https://www.ycombinator.com/companies/digipals/jobs/oZmOW5w-ios-android-full-stack-software-engineering), [Loombotic](https://www.ycombinator.com/companies/loombotic/jobs/7uV8Qj6kZ-software-engineer) |

## Facts that drive the choice

1. **Curation wins first glance.** GitHub advises 3–5 pins; profiles allow up to six. [GitHub Docs](https://docs.github.com/en/account-and-profile/how-tos/profile-customization/pinning-items-to-your-profile)
2. **Make them scannable.** GitHub says reviewers may spend only a couple minutes, so include a README, demo, setup, tests, description, live link, and tags. [GitHub](https://docs.github.com/en/account-and-profile/tutorials/using-your-github-profile-to-enhance-your-resume)
3. **Show collaboration separately.** Mix owned work with meaningful OSS contributions. [GitHub](https://docs.github.com/en/account-and-profile/tutorials/using-your-github-profile-to-enhance-your-resume)
4. **Choose depth you can defend.** GitHub's hiring guide recommends a deep discussion of a candidate project or OSS contribution, alongside communication and teamwork. [GitHub hiring guide](https://github.com/readme/guides/hiring-technical-talent)
5. **Keep extra repos only for a distinct signal**—learning arc, shipped utility, specialty, or collaboration. Archive or unfeature abandoned copies, tutorials, and thin AI wrappers. This is an editorial inference from GitHub's curation guidance.
6. **Seniority changes the proof mix.** New entrants rely more on projects; experienced engineers should foreground employer scope/outcomes in their README and resume.

## Practical default

Make the first screen intentional: **3–5 pins**, a concise profile README, and one flagship repo with a live link and contribution path.

## What this changes for us

Choose **3–5 flagship pins**, not a repo-count target.
Make each one fast to understand, live where possible, and explainable end-to-end.
Use one flagship open project to invite collaborators; make its contribution path explicit.
